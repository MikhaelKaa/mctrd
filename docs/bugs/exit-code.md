# Ошибки завершаются с кодом возврата 0

## Суть

Все ошибки в mctrd печатаются на stdout, но процесс завершается с кодом возврата 0 (`main()` всегда `return 0`, см. src/main.c). Скрипты и CI с `set -e` не останавливаются на ошибке и продолжают работу дальше.

## Проверено (2026-11-11)

| ситуация | вывод программы | код возврата | образ повреждён |
|---|---|---|---|
| `add`, входного файла нет | `Can't open file '...'` | 0 | нет, запись не выполняется (`return` в trdPush до savefile) |
| `pop`, имени нет в каталоге | `Can't find file '...' in image` | 0 | нет |
| `rename`, имени нет в каталоге | `Can't find file '...' in image` | 0 | нет |

Данные при ошибках не теряются: во всех путях ошибки запись образа (`savefile`) не выполняется.

## Влияние

- интерактивное использование: не страшно, сообщение есть;
- скрипты и CI: `set -e` не срабатывает, конвейер продолжается на пустом или неполном образе без видимого сбоя.

## Ожидаемое поведение

Необнуляемый код возврата (1) во всех путях ошибок: `readfile`, `savefile`, `Can't find file`, `No room for file`, `Too many files`, `Unknown image type` и др.
